# DSHTauri

把 DSH 终端的 WebUI 封装成 **Windows 11 轻量桌面应用**：Tauri 2 + 系统原生 **WebView2**（绝不捆绑 Chromium）+ 系统托盘 + 启动时「本地 / 远程」二选一。

> ⚠️ **这是第三方开源客户端，与 DeepSeek 官方无关。** DSHTauri 只是一个**连接客户端**：
> 它**不包含、不捆绑、也不代替** DSH 主程序。使用前请先自行获取并运行 DSH
> —— 官方仓库：<https://github.com/deepseek-ai/deepseek-harness>。
> 详见 [1.1 第三方客户端声明](#11-第三方客户端声明与-deepseek-官方无关)。

- 目标平台：Windows 10/11 x86_64
- 安装包：**NSIS `.exe`**（不用 MSI），单文件安装、无需管理员权限
- 下载：<https://github.com/tianyimc/DSH-Tauri/releases>
- 许可证：[Apache-2.0](LICENSE)
- 代码签名：暂不要求（首次运行会有 SmartScreen 提示，见 [安装](#2-下载与安装)）

## 1. 这是什么

一个**很薄的桌面外壳**：它不自己实现聊天界面，而是把你已经有的 DSH WebUI 装进一个原生窗口里，
并补上桌面应用该有的东西 —— 系统托盘、自定义顶栏、右侧网页对话侧栏、设置窗口、更新检查。

它做什么：

| 能力 | 说明 |
| --- | --- |
| 加载 DSH WebUI | 启动时选择**本地**（如 `http://127.0.0.1:3080`）或**远程**（如 `https://dsh.example.com`）地址 |
| 原生窗口 | 用系统自带的 **WebView2** 渲染，不捆绑 Chromium，安装包只有 1 MB 出头 |
| 系统托盘 | 关闭窗口 = 隐藏到托盘，托盘菜单可唤回窗口、重新选择连接方式、真正退出 |
| 自定义顶栏 | 无系统标题栏，顶部 40px 自绘菜单：应用 / 操作 / 网页对话 |
| 网页对话侧栏 | 点顶栏「网页对话」在右侧展开 <https://chat.deepseek.com/>，可与网页并排或覆盖 |
| 本地服务托管 | 可让应用在连本地时自动后台启动你的本地服务命令（例如 `dsh web`） |
| 设置窗口 | 重新选择连接方式、切换网页对话的加载模式 |
| 检查更新 | 「关于 / 检查更新」窗口直接读 GitHub Releases，Release 与 RC 两条渠道一起列出 |

它**不**做什么：不改动、也不代理你的 WebUI 内容；没有账号体系、没有自己的服务器。

## 2. 下载与安装

### 系统要求

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 x86_64 |
| WebView2 | Win11 自带；Win10 若缺失，**安装器会自动下载并静默引导安装**（`downloadBootstrapper`） |
| 权限 | **不需要管理员权限**（`installMode: currentUser`） |
| 磁盘 | 安装包约 1 MB；运行时占用取决于 WebView2 缓存 |

### 下载

两种方式：

| 方式 | 步骤 | 适合 |
| --- | --- | --- |
| **Release**（推荐） | 仓库页右侧 **Releases** → 点对应版本 → **Assets** 里直接下 `.exe` | 日常使用 / 发给别人 |
| **Artifact**（每次 CI 运行都有） | 仓库 **Actions** → `release-windows` → 运行详情页最下方 **Artifacts** → 下载 zip → 解压得到 `.exe`（Tauri 自己的命名 `DSHTauri_<版本>_x64-setup.exe`） | 测试最新构建 |

安装包文件名按版本规则命名：正式版是 `DSHTauri-v.0.3.3-setup.exe`，
RC 预发布版是 `DSHTauri-v.0.4.0-RC-setup.exe`（规则见 [6.3 版本规则](#63-版本规则)）。
**RC 与正式版各有自己的 tag（`v0.4.0-rc` / `v0.4.0`），可以同时存在，不会互相覆盖。**

### 安装

1. 双击 `DSHTauri-v<版本>-setup.exe`。因为是 `currentUser` 安装，**不弹 UAC**，装到 `%LOCALAPPDATA%\DSHTauri`（即 `C:\Users\<你>\AppData\Local\DSHTauri`）。
2. 安装向导有**选择安装目录**页，默认就有、可以改；完成页可勾选创建桌面快捷方式（**默认不勾**）。
3. 首次启动若系统缺 WebView2，安装器会自动下载引导安装。

**SmartScreen 提示**：因为没做代码签名，Windows Defender 可能提示「未知发布者」——
点「更多信息 → 仍要运行」即可。这是预期行为，不是安装包损坏。

### 这是安装版，不是绿色版

产物是 NSIS 安装程序：会写注册表、建开始菜单快捷方式、带卸载器，**不是**可自由移动的绿色版。

- 会写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<DSHTauri>` 等卸载信息，以及 `HKCU\Software\<publisher>\<productName>`；
- 开始菜单快捷方式：`%AppData%\Microsoft\Windows\Start Menu\Programs\DSHTauri.lnk`；
- 卸载时清理上述注册表项；**只有在卸载确认页勾选了「删除应用数据」时**才会一并删除配置与 WebView2 数据目录（想留着就别勾）；
- 想卸载：**设置 → 应用 → 已安装的应用 → DSHTauri → 卸载**。

> 如果你其实想要**绿色版**：`src-tauri/target/release/DSHTauri.exe` 本身就是单文件可执行程序，
> 拷到哪都能跑（前提是目标机已装 WebView2，Win11 自带）。代价是没有开始菜单快捷方式、没有卸载项、
> 也不会自动装 WebView2。

### 如何无损更新（升级）

**结论：直接下载新版本的安装包，双击装在原来的目录上就行 —— 你的连接地址、设置和登录态都会保留。**

**第一步：先退出程序。** 关闭窗口只是隐藏到托盘（见 [4.4 系统托盘](#44-系统托盘)），
请用 **托盘右键 → 退出** 真正结束进程。安装器会检测到程序还在运行并询问是否关闭它，
但自己先退出更稳妥。

**第二步：下载同渠道的新安装包，双击运行。**
- 用正式版就用正式版的新包（`DSHTauri-v.0.3.3-setup.exe`），用 RC 就用 RC 的新包
  （`DSHTauri-v.0.4.0-RC-setup.exe`）；文件名规则见 [6.3 版本规则](#63-版本规则)。
- 安装目录会沿用上次的位置（`RestorePreviousInstallLocation` 会从注册表读回你上次选的目录），
  所以**不需要**再手动选一次；默认位置是 `%LOCALAPPDATA%\DSHTauri`。

**第三步：安装完直接启动。** 地址、设置、登录态都还在，不需要重新配置。

#### 为什么是无损的

关键在于**安装目录和你的数据是两个不同的地方**：

| 内容 | 实际位置 | 更新时 |
| --- | --- | --- |
| 程序本体（`DSHTauri.exe`、`uninstall.exe`、图标） | `%LOCALAPPDATA%\DSHTauri`（安装目录，`installMode: currentUser`） | **会被替换**——这正是更新的目的 |
| 连接地址与设置（本地 / 远程 URL、自动启动命令、网页对话加载模式） | `%APPDATA%\com.dsh.dshtauri\config.json`（应用配置目录，在安装目录之外） | ✅ 原样保留 |
| 登录态（Cookie / localStorage / 缓存） | `%LOCALAPPDATA%\com.dsh.dshtauri\webview2`（WebView2 用户数据目录，在安装目录之外） | ✅ 原样保留 |

因为后两者都在 `%LOCALAPPDATA%\DSHTauri` **之外**，安装器只覆盖安装目录里的文件，
碰不到它们，所以升级后配置和登录态都还在（详见 [4.6 登录态与 Cookie](#46-登录态与-cookie)
与 [6.4 数据与配置文件](#64-数据与配置文件)）。

#### 什么情况下会丢

更新本身不会丢东西；下面这几种**主动操作**才会：

- **卸载时勾选「删除应用数据」**：卸载器会删掉 `%APPDATA%\com.dsh.dshtauri` 和
  `%LOCALAPPDATA%\com.dsh.dshtauri`（配置 + 登录态）。想留着数据就**不要勾**这个框。
  正常「覆盖安装 / 更新」时该删除逻辑会被跳过，不会动你的数据。
- **改应用 `identifier`**（只影响自己构建的人）：等于换了一个配置目录与 profile，
  旧地址与登录态都会「消失」。详见 [5. 常见问题与排查](#5-常见问题与排查)。
- **换用绿色版**：数据位置不变，配置和登录态仍在；但绿色版没有开始菜单快捷方式、没有卸载项，
  也不会自动装 WebView2（见上面「这是安装版，不是绿色版」）。

> **渠道提醒**：正式版和 RC 版共用同一个 `identifier`，所以数据位置相同 ——
> 从正式版换到 RC（或换回来）**不会丢数据**。但 RC 是预发布版，
> 在 GitHub Releases 里标记为 *prerelease*，可能不稳定；日常使用建议留在正式版。
> 跨渠道更新前，「关于 / 检查更新」窗口也会先让你确认一次。

## 3. 首次启动

启动后先出现「选择 DSH 连接方式」窗口（首次使用时两个地址都还没配）：

```text
┌──────────────────────────────────────────────┐
│ ● 选择 DSH 连接方式                    [设置] │
├──────────────────────────────────────────────┤
│ ⌂  本地                                      │
│    未配置（点击填写）              [未配置]   │   ← 虚线框、半透明
├──────────────────────────────────────────────┤
│ ☁  远程                                      │
│    未配置（点击填写）              [未配置]   │   ← 虚线框、半透明
├──────────────────────────────────────────────┤
│ 状态：请选择连接方式；首次使用需要先填写地址。│
│ 还没配置地址：点「设置」填写…       v.0.3.3 │
└──────────────────────────────────────────────┘
```

配好之后，卡片显示实际地址和状态徽章：

```text
│ ⌂  本地                                      │
│    http://127.0.0.1:3080      [自动启动服务] │
│ ☁  远程                                      │
│    未配置（点击填写）              [未配置]   │
```

**每次启动都要选，地址只设置一次**：

- **每次启动都显示选择界面**，必须点「本地」或「远程」——「选择」本身不持久化；
- **首次**点击时弹出表单让用户确认地址，保存进 `config.json`——「地址」持久化；
- 之后每次启动读同一份配置，点一下就直接连接，**不需要再设置地址**；
- 地址随时可在「设置」里改。

**本地和远程允许只配一个**：

- 两个地址默认都是空的，用户按需填一个即可，另一个留空；
- 两个都留空不允许（保存时会提示「至少要填一个」）；
- 未配置的那一侧卡片仍是**可点击**的（不是死按钮）——点了会直接打开设置面板去补。

首次点击时展开的表单：本地 URL、远程 URL（各带「可留空」标注和示例 placeholder）、
**勾选「选择本地时自动执行下面的命令」**、以及 PowerShell 启动命令（placeholder 示例 `dsh web`）。

## 4. 使用说明

### 4.1 顶栏菜单

主窗口**没有系统标题栏**，顶部 40px 是自绘菜单栏（仍然可以拖边缘缩放，也可以拖顶栏移动窗口）：

```text
主窗口 main（1200x800，无系统标题栏）
┌──────────────────────────────────────────────────────────────────────┐
│ 应用 ▾   操作 ▾   网页对话              （拖动区域）      ─   □   ✕   │  ← 顶栏 40px
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                        DSH WebUI（你配置的本地 / 远程页面）            │
│                                                                      │
│                                          ┌────────────────────────┐  │
│                                          │ 网页对话                │  │
│                                          │ chat.deepseek.com       │  │
│                                          └────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

| 菜单 | 展开项 | 行为 |
| --- | --- | --- |
| **应用** | 关于 / 检查更新 / 重新连接 | 关于 → 打开「关于」窗口；检查更新 → 打开并自动检查 GitHub Releases（Release 与 RC 两条渠道）；重新连接 → 与托盘「重新选择连接方式」**完全相同** |
| **操作** | 刷新 / 撤销 / 重做 | 刷新 = 重新加载当前页面（等同 F5）；撤销 / 重做 = 对网页发真实的 **Ctrl+Z / Ctrl+Y** |
| **网页对话** | （无下拉，直接动作） | 切换右侧侧栏，加载 <https://chat.deepseek.com/> |

### 4.2 网页对话侧栏与两种加载模式

点顶栏「**网页对话**」在右侧展开对话侧栏（首次点击时创建），**再次点击即隐藏**。

在「设置」里可切换加载模式：

| 模式 | 网页 | 聊天 | 说明 |
| --- | --- | --- | --- |
| `overlay`（默认） | 整宽不变 | 覆盖在网页右侧**之上** | 与旧版行为一致；网页面积不受影响 |
| `docked` | 让出右侧固定宽度 | 与网页**并排**、不重叠 | 便于一边看网页一边聊天；网页变窄 |

两种模式都**不改变程序窗口本身的尺寸**（宽度严格守恒：网页宽 + 侧栏宽 = 窗口宽）。
侧栏开/关在 `overlay` 模式下有 180ms 的滑入/滑出动画，并跟随 Windows 11「动画效果」开关。

### 4.3 「设置」窗口

顶栏「**应用 → 设置**」打开（独立窗口），提供：

- **重新选择连接方式** —— 与托盘菜单 / 顶栏「应用 → 重新连接」**同一分支**，行为完全一致。
- **网页对话的加载方式** —— [上面两种模式](#42-网页对话侧栏与两种加载模式)二选一，立即生效并落盘。

### 4.4 系统托盘

- **关闭窗口（`X`）= 隐藏到托盘**，程序继续在后台运行；任务栏图标可能仍在（正常现象）。
- **托盘左键单击** → 直接唤出主窗口；**右键** → 菜单：

| 菜单项 | 行为 |
| --- | --- |
| 显示主窗口 | 唤出/显示主窗口 |
| 重新选择连接方式 | 把选择窗口叫回来，重新选本地 / 远程 |
| 退出 | **真正的退出**，进程结束 |

- 托盘图标随系统浅色/深色主题自动切换。
- 找不到托盘图标？见 [5. 常见问题与排查](#5-常见问题与排查)。
- 想彻底退出：托盘右键 →「退出」（关闭窗口只是隐藏）。

### 4.5 本地服务怎么启动

连「本地」时，你的本地服务（例如 `dsh web`）需要先跑起来。三种方式，按需选：

| 方式 | 做法 |
| --- | --- |
| **手动启动**（默认） | 设置里不勾「自动执行命令」，自己先跑 `dsh web`，再点「本地」 |
| **应用自动启动**（推荐） | 设置里勾上并填写命令，例如 `Set-Location C:\dsh; dsh web`。应用会后台启动它，然后轮询端口，就绪后打开主窗口 |
| **外部守护** | 用计划任务 / NSSM 把服务注册成开机自启，应用只负责连 `http://127.0.0.1:3080` |

自动启动的服务会随主程序退出而结束（不会留下孤儿进程）。

### 4.6 登录态与 Cookie

- **Cookie 与登录态跨重启保留**：应用把 WebView2 的用户数据目录固定到
  `%LOCALAPPDATA%\com.dsh.dshtauri\webview2`，Cookie、localStorage、IndexedDB、缓存都会落盘，**登录一次即可**。
- 应用会在启动时把**会话 Cookie 转成持久 Cookie**，所以关掉程序再开也还在登录态。
- **本地服务和远程站点之间不会共享登录态**：它们的 origin 不同，各自独立。
- 覆盖安装 / 更新**不会**影响登录态（该目录在安装目录之外），详见 [如何无损更新](#如何无损更新升级)。

## 5. 常见问题与排查

完整版见 **[docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)**。用户最常遇到的几条：

| 现象 | 先看这里 |
| --- | --- |
| **连不上 / 一直转圈** | 本地服务是否已在监听？在设置里检查地址（必须是 `http://` 或 `https://` 开头）。远程地址是否可达 |
| **页面白屏** | [TROUBLESHOOTING §6 WebView2 加载远程 URL 白屏](docs/TROUBLESHOOTING.md#6-webview2-加载远程-url-白屏)；另外 `https://` 页面里请求 `http://127.0.0.1:3080` 会被 WebView2 按混合内容拦截，本地服务请用 `http://` 直接打开 |
| **每次都要重新登录 / 登录态丢了** | 见 [4.6 登录态与 Cookie](#46-登录态与-cookie)；如果你改过应用的 `identifier`，等于换了 profile，登录态会「丢失」 |
| **托盘区找不到图标** | 大概率被 Windows 折叠进「隐藏的图标」面板（点 `^` 能看到），拖到任务栏常驻即可。详见 [TROUBLESHOOTING §1 托盘图标不显示](docs/TROUBLESHOOTING.md#1-托盘图标不显示) |
| **点了 `X` 程序没退，或想彻底退出** | 这是设计行为：关闭 = 隐藏到托盘。彻底退出用 **托盘右键 → 退出**。详见 [TROUBLESHOOTING §2 关闭窗口未隐藏到托盘](docs/TROUBLESHOOTING.md#2-关闭窗口未隐藏到托盘程序直接退出了) |
| **首次运行被 SmartScreen 拦住** | 未做代码签名，点「更多信息 → 仍要运行」，属预期行为 |
| **远程页面里某些功能没反应** | 远程页面默认**不授予**本地 IPC 权限（安全默认）。这是有意的取舍，详见 [TROUBLESHOOTING §5 remote capabilities 权限错误](docs/TROUBLESHOOTING.md#5-remote-capabilities-权限错误) |

**「关于 / 检查更新」报「检查失败」**：离线或被网络策略拦截时属正常，不影响使用；
也可以直接到 <https://github.com/tianyimc/DSH-Tauri/releases> 看最新版本。

> 如果你是**在源码上构建**时遇到报错（`npm run tauri dev`、NSIS 打包、图标格式、`cargo metadata` 等），
> 那属于贡献者场景：请看 **[CONTRIBUTER_README.md](CONTRIBUTER_README.md)** 的
> [排错用的环境自检与日志命令](CONTRIBUTER_README.md#11-排错用的环境自检与日志命令) 一节。

### 6.3 版本规则

版本号形如 **`v.A.B.C`**，例如 `v.0.3.3`。三个数字是 DSHTauri 自己的语义：

| 位 | 含义 | 当前值 |
| --- | --- | --- |
| `A` | **大版本**。桌面外壳整体换代、或有破坏性改动时才提升。 | `0` |
| `B` | **功能版本**。新增用户可见的功能（如设置窗口、网页对话侧栏）。 | `3` |
| `C` | **修订版本**。小功能、优化与 bug 修复。 | `3` |

**两个发布渠道**

| 渠道 | 显示 | 含义 |
| --- | --- | --- |
| **Release**（正式版） | `v.0.3.3`（无后缀） | 稳定版，日常使用选它 |
| **RC**（预发布版） | `v.0.4.0 RC`（空格 + `RC`） | 发布前的候选版，抢先体验用；在 GitHub 上标记为 *prerelease* |

**发布产物命名**（同一个 `A.B.C` 下，RC 与正式版各有自己的 tag，可以同时存在、互不覆盖）：

| 渠道 | 显示版本 | 安装包文件名 | Git tag | Release 标题 | GitHub prerelease |
| --- | --- | --- | --- | --- | --- |
| Release | `v.0.3.3` | `DSHTauri-v.0.3.3-setup.exe` | `v.0.3.3` | `DSHTauri v.0.3.3` | 否 |
| RC | `v.0.4.0 RC` | `DSHTauri-v.0.4.0-RC-setup.exe` | `v.0.4.0-rc` | `DSHTauri v.0.4.0 RC` | 是 |

> 注意显示名和文件名里的后缀写法不同：**显示**用空格（`v.0.4.0 RC`），
> **文件名**用 `-RC`（`DSHTauri-v.0.4.0-RC-setup.exe`），**tag** 用小写 `-rc`（`v.0.4.0-rc`）。

**当前版本：`v.0.3.3`**（渠道 `release`，无后缀）。

> 「当前版本」指仓库里正在开发的版本号；**能不能下载到，以
> [Releases](https://github.com/tianyimc/DSH-Tauri/releases) 页面上实际存在的产物为准**。
> 每个版本改了什么见 [CHANGELOG.md](CHANGELOG.md)。

**在程序里也看得到**：选择窗口右下角显示当前版本；托盘悬浮提示是 `DSHTauri v.0.3.3`。

**「关于 / 检查更新」怎么判断有没有新版**

- 点「关于 → 检查更新」会**同时检查 Release 与 RC 两个渠道**，并在窗口里**分两组一起列出**
  各自的版本，你能一眼看到两条线各到哪了。
- 当前运行的是哪个渠道，窗口上会有标记；如果某条渠道还没发布过，会提示「暂无 RC 预发布版本」之类的说明，这不是错误。
- **跨渠道下载前会先让你确认**（例如你正在用 Release，却想下 RC 版）——
  确认面板会点名两个渠道，避免误装。
- 离线或被网络策略拦截时会提示「检查失败」，属正常，不影响使用；
  也可以直接到 <https://github.com/tianyimc/DSH-Tauri/releases> 看。

**发版步骤**（面向维护者；命令细节见 [CONTRIBUTER_README.md §0.5](CONTRIBUTER_README.md#05-版本号工具与发版流程)）

1. 改版本号：`node scripts/version.mjs --set 0.3.3`（同步三处版本号）。
2. 切渠道：`node scripts/version.mjs --set-channel rc` 发 RC，或
   `node scripts/version.mjs --set-channel release` 发正式版。
3. 在 [CHANGELOG.md](CHANGELOG.md) 顶部加一条对应版本的记录。
4. 提交推送；CI 会用 `node scripts/version.mjs --github` 推导 tag、标题和安装包名自动出包。
   **RC 发布为 GitHub prerelease**，正式版为普通 Release。

> 版本号状态存在仓库根目录的 `version.json`（`{"channel":"release"}`），
> `A.B.C` 则在 `src-tauri/tauri.conf.json`。每个版本改了什么，见 [CHANGELOG.md](CHANGELOG.md)。

### 6.4 数据与配置文件

| 内容 | 位置 |
| --- | --- |
| 连接地址与设置（本地 URL、远程 URL、自动启动命令、网页对话加载模式） | `%APPDATA%\com.dsh.dshtauri\config.json` |
| Cookie / localStorage / 缓存（登录态） | `%LOCALAPPDATA%\com.dsh.dshtauri\webview2`（WebView2 用户数据目录） |
| 程序本体（`DSHTauri.exe` / `uninstall.exe`） | `%LOCALAPPDATA%\DSHTauri`（安装目录） |

- `config.json` 是可读的 JSON，可以手工编辑或删除（删除后下次启动会重新问你地址）。
- 上面前两行都在**安装目录之外**，所以覆盖安装 / 更新不会动它们（见 [如何无损更新](#如何无损更新升级)）。
- 卸载时若勾选「删除应用数据」，会清理 `%APPDATA%\com.dsh.dshtauri` 与 `%LOCALAPPDATA%\com.dsh.dshtauri`；
  不勾选则保留配置与登录态。
