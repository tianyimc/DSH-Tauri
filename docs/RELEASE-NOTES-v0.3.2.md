## 本次更新

### 修复：并排（docked）模式的过渡动画

上一版修好了「浮层（overlay）」模式的侧栏动画，但**并排模式**没有一起改 ——
它当时**完全不做滑动**，直接切到位，所以看起来仍是「啪一下跳过去」，
切换瞬间还会闪一下。

**根因不是「没有动画」，而是顺序**：关闭时先把内容页宽度立刻还回去、紧接着隐藏侧栏，
中间没有任何过渡，右侧会先露出一条**没有页面覆盖的空带**（深色主题下就是白闪）。

**现在两种模式共用同一条滑动路径**：

| 模式 | 滑动过程中内容页 | 内容页何时变化 | 重排次数 |
| --- | --- | --- | --- |
| 浮层（overlay） | 整宽不变 | 不变化 | **0** |
| 并排（docked）· 打开 | **整宽不变** | 侧栏滑到位后才让出宽度 | **1** |
| 并排（docked）· 关闭 | 立即还原 | 起动画后立即还原 | **1** |

关键：并排模式那**一次**必然发生的重排被挪到「侧栏已经盖住右侧之后」，
所以**滑动过程本身零重排**（与浮层模式同质），空带不再露出来。

> 诚实说明：并排模式**必然**要重排一次内容页（并排本来就要让出宽度），
> 本版做的是把这次重排从「滑动过程中、露出空带」挪到「滑动结束、被侧栏遮住时」。

### 修复：开始菜单图标仍是旧图

**现象**：开始菜单里的快捷方式显示的是旧的「白色圆角方块 + 深色鲸鱼」，
不是上一版统一的透明鲸鱼。

**根因有两层**（缺一不可）：

1. Tauri 的 NSIS 模板创建快捷方式时**没有指定图标文件**，于是图标继承 exe 内嵌资源，
   无法单独控制；
2. 模板的快捷方式创建函数在**更新模式**下**直接返回** —— 也就是说
   **覆盖安装永远不会修好已经存在的旧快捷方式**。这正是「程序里的图标早就换了、
   开始菜单却还是旧的」的原因。

**修法**：

- 新增开始菜单专用图标 `startmenu.ico` = **白鲸鱼 + 细描边**。
  快捷方式的图标是**静态**的、**不会跟随系统深浅色**，所以用深浅背景都能看清的配色
  （深藏青版在深色开始菜单上几乎看不见；纯白版在浅色开始菜单上同样看不见）。
- 安装器新增一个**在更新模式下也会执行**的收尾钩子：重建开始菜单快捷方式并指定新图标，
  然后通知系统**刷新图标缓存**（否则即使文件已改对，资源管理器仍显示缓存里的旧图标）。

### 修复：任务栏按钮图标不跟随主题

**现象**：深色任务栏上，任务栏按钮里的深藏青鲸鱼几乎看不见。

**根因同样是两层**：

1. Tauri 的「设置窗口图标」最终**只设置了小图标槽**，而**任务栏按钮渲染的是大图标槽**
   —— 所以任务栏一直在用 exe 里那个固定图标，怎么改都影响不到它；
2. 任务栏跟随的是**系统（外壳）深浅色**，而程序读到的是**应用深浅色**。
   在「个性化 → 颜色」里选「自定义」时两者可以不一致，
   于是会给深色任务栏配上深色图标。

**修法**：新增一个专门的 Windows 模块，直接给窗口的大图标槽设置按主题选出的图标，
并且**按系统（外壳）主题选色**（系统托盘同理 —— 它也长在任务栏上）。

### 变更：版本规则改为 RC / Release 双通道

- 版本号格式为 **`v.A.B.C`**；**`GenX` 规则已取消**。
- **RC 版**（release candidate，候选版）显示为 **`v.0.3.2 RC`**；
  **Release 版**不带任何后缀。
- GitHub 发布时 RC 版会**自动标记为预发布**（prerelease），
  tag 用 `v.0.3.2-rc`、正式版用 `v.0.3.2`，两者**不会互相覆盖**。
- 切换渠道：`node scripts/version.mjs --set-channel release|rc`
  （原来的 `--bump-gen` 已移除）。

### 变更：「关于 → 检查更新」同时检查两条通道

- 一次点击会**同时查询 RC 与 Release 两条通道**，把结果**并列显示**，
  并标出当前运行的是哪一条。
- 若你要下载的是**另一条通道**的版本（例如当前是 Release 版却要下 RC 版），
  会先弹出确认，说明两条通道的区别，确认后才开始下载。

### 内部

- 删除历史遗留、已无代码引用的图标素材与脚本（旧的 `app-icon.png`、两个旧 `.ico`、
  以及生成它们的脚本）。图标现在只有**一个**来源，不再有「生成两套再覆盖回去」的绕路。
- 静态校验从 39 项增加到 **64** 项；每一项都做了**变异测试**（故意改坏代码，确认校验会失败）。

## 安装与更新

1. 下载 `DSHTauri-v.0.3.2-setup.exe`。
2. 运行安装程序。首次运行可能出现 SmartScreen 提示（未做代码签名），
   选择「更多信息 → 仍要运行」即可。
3. 安装时**默认不勾选**「创建桌面快捷方式」，需要的话在完成页自行勾选。

**无损更新**：直接下载新版本安装包**覆盖安装**即可，配置与登录态都在安装目录之外，
不会丢失。详见 [README「如何无损更新」](../README.md#如何无损更新升级)。

系统要求：Windows 10/11 x64（需要 WebView2 运行时，安装包会自动处理）。

## 如何真正发布（尚未执行）

本版本已准备好，但**没有**创建 Release。要发布时：

```bash
# 在 GitHub 上手动触发 workflow，并勾选 create_release
gh workflow run release-windows.yml -f create_release=true
```

或在仓库 **Actions → release-windows → Run workflow** 中勾选
「构建完成后创建 GitHub Release 并附带 NSIS 安装包」。

发布后会创建 tag `v.0.3.2`，并附上 `DSHTauri-v.0.3.2-setup.exe`。

> 注意：普通 push 到 `main` **只会构建 + 跑冒烟测试**，不会发布 Release
> （release job 有 `if: github.event_name == 'workflow_dispatch' && inputs.create_release` 守卫）。
>
> 若要发 **RC 预发布版**：先 `node scripts/version.mjs --set-channel rc` 并提交，
> 再触发 workflow —— 它会自动把 Release 标记为 prerelease，tag 为 `v.0.3.2-rc`。
