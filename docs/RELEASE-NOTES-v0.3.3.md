### 修复：「关于 / 设置」窗口左上角的图标不跟随主题

**现象**：主窗口的图标能跟着系统深浅色变，但「关于」和「设置」窗口左上角
一直是那只**深藏青**的鲸鱼（深色标题栏上几乎看不见）。

**根因是「创建时机」而不是「有没有做适配」**：

- 图标统一逻辑只在三个时刻执行：程序启动、主窗口创建、系统主题切换；
- 而「关于」/「设置」窗口是**你点菜单时才创建**的，远晚于上面那些时刻。

于是它们拿到的是安装包里那个**固定深藏青**的静态图标，之后再没有任何机会被纠正。

**修法**：每个窗口创建完成后立刻设置一次当前主题对应的图标。
另外把主题来源改成**直接读系统设置** —— 因为创建**第一个**窗口（选择窗口）时
一个窗口都还没有，没有对象可以询问主题，否则浅色系统上会错误地使用白色鲸鱼。

### 修复：「关于 / 设置」页内的 logo 还是 emoji

**现象**：页面左上角显示的是 emoji（`🐋` / `⚙️`），与程序其它各处（托盘、任务栏、
标题栏）用的统一鲸鱼**不是同一只**。

**修法**：改用真实的图片资源，按系统深浅色自动切换
—— 深色背景用白鲸鱼、浅色背景用深藏青鲸鱼，与其余各处**完全同一只**。

### 修复：页内外部链接会把「关于」窗口顶掉

「关于」页里的作者链接等外链，在 WebView2 里点击时**可能不会打开新窗口**，
而是把「关于」窗口自己导航过去 —— 点一下界面就变成网页、回不来了。

**修法**：页内所有 `http`/`https` 外链统一交给**系统默认浏览器**打开
（与「检查更新」的下载按钮走同一条路径），本窗口不再发生导航。

## 安装与更新

1. 下载 `DSHTauri-v.0.3.3-setup.exe`。
2. 运行安装程序。首次运行可能出现 SmartScreen 提示（未做代码签名），
   选择「更多信息 → 仍要运行」即可。
3. 安装时**默认不勾选**「创建桌面快捷方式」，需要的话在完成页自行勾选。

**无损更新**：直接下载新版本安装包**覆盖安装**即可，配置与登录态都在安装目录之外，
不会丢失。详见 [README「如何无损更新」](../README.md#如何无损更新升级)。

系统要求：Windows 10/11 x64（需要 WebView2 运行时，安装包会自动处理）。

## 如何真正发布（尚未执行）

本版本已准备好，但**没有**创建 Release。要发布时：

```bash
# 在 GitHub 上手动触发 workflow，并勾选 create_release
gh workflow run release-windows.yml -f create_release=true
```

或在仓库 **Actions → release-windows → Run workflow** 中勾选
「构建完成后创建 GitHub Release 并附带 NSIS 安装包」。

发布后会创建 tag `v.0.3.3`，并附上 `DSHTauri-v.0.3.3-setup.exe`。

> 注意：普通 push 到 `main` **只会构建 + 跑冒烟测试**，不会发布 Release
> （release job 有 `if: github.event_name == 'workflow_dispatch' && inputs.create_release` 守卫）。
>
> 若要发 **RC 预发布版**：先 `node scripts/version.mjs --set-channel rc` 并提交，
> 再触发 workflow —— 它会自动把 Release 标记为 prerelease，tag 为 `v.0.3.3-rc`。
