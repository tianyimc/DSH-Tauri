# DSHTauri v.0.3.4 发布说明

**主题：内存与后台行为优化 + 可复现的内存测量。**

---

## 一句话总结

本版让**不可见的页面停止消耗 CPU**、让**「关于 / 设置」关闭后真正释放内存**，
并第一次把内存测量做进了 CI（每次提交都能看到真机数字）。

但必须诚实说明：**对任务管理器里那个常驻内存数字，本版几乎没有改善。**
原因见下面「实测结论」——这与 WebView2 挂起 API 的语义有关，不是实现失误。

---

## 变更

### 1. 新增内存测量（每次 CI 都会打印）

以 `dshtauri.exe` 为根，递归统计 WebView2 全部子进程的内存，在 6 个阶段各采一次样：

| 采样点 | 含义 |
| --- | --- |
| 1-选择窗口 | 只有启动界面 |
| 2-连接后（未开侧栏） | 顶栏 + 内容页 |
| 3-侧栏已打开 | 多一个 chat.deepseek.com |
| 4-侧栏已关闭 | 关键对比点 |
| 5-已收进托盘 | 关键对比点 |
| 6-从托盘恢复 | 验证恢复 |

同时记录**系统可用内存**（解释挂起效果必需）与 WebView2 进程数。

### 2. 不可见的页面会被「挂起」

用 WebView2 的 `TrySuspend`（等价 Edge 的「标签页休眠」）：

- 关闭「网页对话」侧栏后 → 挂起 `chat`；
- 收进系统托盘时 → 挂起内容页与侧栏。

挂起会**暂停页面脚本定时器与动画、停止 CPU 占用**，并把内存标记为「系统可回收」。
重新可见时自动恢复，**不会重新加载页面**（所以未发送的文字不会丢）。

### 3. 「关于」/「设置」窗口关闭即销毁

此前只是隐藏，renderer 一直占着内存。这两个是本地小页面，重建很快。
重建带一次重试，避开「旧 WebView2 尚未释放」的竞态。

### 4. 连接成功后销毁「选择窗口」

它是一次性的「选连接方式」界面，主窗口起来后就没用了，留着只会白占一个 renderer。
销毁后仍可从托盘「重新选择连接方式」把它**重建**出来（重建带重试）。

- **没有主窗口时只隐藏、不销毁** —— 那时它是唯一窗口，销毁最后一个窗口会让程序
  直接退出（托盘也一起消失），而点「×」通常只是想把它收起来。
- 销毁刻意**延后 250ms、在异步线程上**执行：这条链路正是选择窗口自己发起的 IPC，
  历史上在「它的 IPC 回调里」销毁它自己会让 Windows 消息处理进入坏状态
  （后续 `hide()` 被丢弃 ⇒ 点 × 没反应），所以必须等 IPC 返回后再销毁。

## 实测结论（重要，请读完）

CI（windows-latest）实测：**挂起 API 确实调用成功**（应用日志里有
`[DSHTauri] 已挂起 webview（TrySuspend 成功）`），**但内存数字没有下降**：

| 采样点 | 工作集 MB | 私有 MB |
| --- | --- | --- |
| 3-侧栏已打开 | 667.8 | 281.4 |
| 4-侧栏已关闭 | 669.3 | 280.2 |
| 5-已收进托盘 | 666.0 | 280.2 |

关侧栏、收托盘之后，内存**基本没变**。

### 为什么

微软文档对 `TrySuspend` 的定义是：

> *"Suspending ... **allows the operating system to reuse** the memory that was
> used by the renderer process"*

即把内存标记为**可回收**，而**不是立刻释放**。测试机上系统可用内存约 13GB，
内核没有回收压力，所以数字不动。

### 所以本版的实际收益

1. **不可见页面不再消耗 CPU**（定时器、轮询、动画全部暂停）—— 对笔记本续航和
   后台占用是实打实的改善；
2. **内存变为可回收** —— 在内存紧张的机器上可被系统回收，缓解压力；
3. **「关于 / 设置」关闭后 renderer 真正释放** —— 这部分是确定的下降。

### 想进一步降低常驻内存，需要「销毁」而不是「挂起」

| 对象 | 可省（私有） | 代价 | 状态 |
| --- | --- | --- | --- |
| 选择窗口 | 一个本地小页面 renderer（数十 MB 量级） | 每次「重新选择连接方式」需重建（本地小页面，很快） | ✅ **本版已做** |
| 对话侧栏 | 约 **100MB** 增量（实测：多开一个重型页面 = 私有 +109MB） | 每次打开需重新加载 chat.deepseek.com（明显变慢，可能丢草稿） | ❌ 未启用 |

> 选择窗口与「关于 / 设置」的销毁是**真实释放**（renderer 进程真的被关掉），
> 与「挂起」不同 —— 这部分内存下降是确定的。侧栏的销毁**未启用**：
> 它的代价（重开变慢、可能丢未发送草稿）明显更大。
